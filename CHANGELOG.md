# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `_DetectorBase.estimate_parameters` (and all detector subclasses that inherit it) now sets four new attributes when EM finishes: `converged_` (`bool` — True if EM met its tolerance before `max_iter`), `n_iter_` (`int` — number of EM iterations actually performed), `em_monotonicity_violations_` (`list[int]` — 1-based iteration indices where the marginal log-likelihood decreased, empty when EM is well-behaved), and `degenerate_timesteps_` (`np.ndarray` — 0-based time indices where the final E-step had all-`-inf` log-likelihoods and fell back to the predicted distribution, empty when none occur). The indices are collected during the filter's forward pass (via the chunked drivers' `degenerate_indices_out` collector), so they are reliable regardless of `n_chunks` or whether likelihood caching is enabled — they do not depend on the returned log-likelihoods, which are `None` when uncached. All four attributes are initialized together after input validation, so a fit that fails validation leaves none of them set.
- `likelihoods.gmm.GaussianMixtureModel.converged_` now reflects the actual EM lower-bound convergence flag from `_em_fit_while_loop`, replacing the prior heuristic `n_iter < max_iter`. A `UserWarning` is emitted at the end of `fit` when the model did not converge.
- `likelihoods.sorted_spikes_glm.fit_poisson_regression` now emits a `UserWarning` when the fitted model leaves a large final gradient (inf-norm above `GLM_CONVERGENCE_GRAD_TOL = 1e-3`), including the gradient norm, BFGS message, iteration count, and final loss. Convergence is judged by the actual gradient rather than SciPy's `success` flag, because BFGS routinely reports `success=False` ("precision loss") at a perfectly good minimum; gating on the gradient avoids a near-constant spurious warning.
- `core._condition_on` now distinguishes two non-finite cases. A degenerate timestep where **every** state is `-inf` (impossible data) falls back to the predicted distribution with `log_norm=-inf` (previously emitted an invalid all-zero posterior that also poisoned every subsequent timestep). A timestep containing a `NaN` (a likelihood-computation bug, not impossible data) is **no longer masked**: the NaN propagates into the posterior so the problem stays visible. The fallback now triggers only on `ll.max() == -inf`, so a finite state alongside a `-inf` state is still used. The host-side `filter`, `filter_covariate_dependent`, `chunked_filter_smoother`, and `chunked_filter_smoother_covariate_dependent` functions log one `logger.warning` for degenerate timesteps and a separate one for NaN timesteps when any are found. The host-side diagnostics in `filter` / `filter_covariate_dependent` are skipped when the input is a JAX tracer, so those wrappers remain composable inside `jit`/`vmap`/`scan` (the pure filtering computation still runs).
- `model_checking.highest_posterior_density.get_HPD_spatial_coverage`: optional `bin_width` parameter for non-uniformly-spaced 1D (linearized track-graph) grids. Multi-segment tracks with unequal arm lengths produce on-track bins of different widths (plus `edge_spacing` gap bins); the default uniform path used the first bin's width for every bin, biasing coverage. Pass per-bin widths — e.g. `np.diff(environment.edges_[0])` — to integrate the exact bin measure. The default (no `bin_width`) is unchanged and remains exact for open-field grids and single-segment tracks (which `Environment` builds with equal-width bins); non-uniform widths cannot be recovered from bin centers alone.
- `_DetectorBase.estimate_parameters` now writes the fitted discrete initial-condition distribution to `self.discrete_initial_conditions_` (trailing underscore, sklearn fitted-attribute convention) instead of overwriting the user-supplied `self.discrete_initial_conditions` constructor argument. `sklearn.clone(fitted_model)` now correctly reproduces the original user spec.
- `environment.find_environment_by_name(environments, name)`: new helper that replaces the previous `environments.index(name)` pattern. The old pattern relied on the now-removed `Environment.__eq__(self, other: str)` override.
- `ClusterlessDetector._resolve_clusterless_algorithm_params()` and `SortedSpikesDetector._resolve_sorted_spikes_algorithm_params()`: new private helpers that return a fresh copy of the algorithm params at each call, with `None` resolved to a fresh copy of the module-level default. Replaces the previous in-`__init__` dict-copy approach so that `sklearn.clone()` works.

### Fixed

- `analysis.distance1D.get_map_speed`: the trailing boundary speed was inserted before the last array element instead of appended; for every chunk with three or more time bins, the final two speed samples were misordered.
- `models.base._DetectorBase.estimate_parameters`: post-EM cleanup of the encoding-model data did nothing because the attribute name in the `hasattr` check did not match the leading-underscore form used at write sites; spike-time and waveform-feature arrays were retained for the lifetime of every fitted model.
- `models.cont_frag_model.ContFragSortedSpikesClassifier.get_posterior` and `ContFragClusterlessClassifier.get_posterior`: raised an exception for 2D environments because the implementation summed over the dimension name `"position"`, which only exists for 1D environments. Now collapses every dimension whose name matches `"position"` or ends with `"_position"`, supporting 1D, 2D, and higher-D environments. The returned dim is still named `state` (singular), so existing `state_probs.sel(state="Continuous")` callers continue to work.
- `environment.Environment.fit_place_grid`: a tuple `place_bin_size` provided with a `track_graph` previously dereferenced a dead local variable and reached a confusing `TypeError` deep inside `np.linspace`. Now raises a clear `ValidationError` explaining the constraint and showing an example.
- `continuous_state_transitions.RandomWalk`: `direction`-aware transitions on an environment lacking an N-D track graph and array-typed inter-node distances would crash with `AttributeError` deep inside `networkx`. Now raises a clear `ConfigurationError` with a hint pointing to the two valid configurations.
- `visualization.figurl_2D.process_decoded_data`: linearized bin indices stored as `uint16` would silently wrap modulo 65536 once the largest index exceeded 65535, corrupting the rendered decoded-position view. The largest index for an `x_count × y_count` grid is `x_count*y_count - 1`, so overflow begins at 65537 bins (a 256×256 grid has 65536 bins and a max index of 65535, which still fits). The check is now factored into `validate_grid_within_uint16`, which raises a clear `ValueError` at that boundary; the `uint16` dtype is retained because the downstream `sortingview.views.franklab.DecodedPositionData` schema receives these indices as `uint16`.
- `model_checking.highest_posterior_density.get_HPD_spatial_coverage`: only computed a 1D bin width even though its docstring advertised 2D support; for 2D posteriors it either crashed (no `position` dim) or returned wrong units. It now detects the position dimensions by name and integrates over the bin measure — the product of the per-axis bin widths — supporting 1D (length), 2D (area), 3D (volume), and higher-dimensional posteriors.
- `models.base` position-dimension naming: the canonical position-dim names (`position`; `x`/`y`/`z`/`w`/`v`/`u`_position for 2-6D; `dim{i}_position` beyond six) were re-derived independently in several places, and `_convert_seq_to_df` capped its labels at four (`x`/`y`/`z`/`w`) and silently dropped the extra position columns for 5- and 6-dimensional environments. The convention is now defined once in `non_local_detector._position_dims` (`get_position_dim_names` / `get_position_dims`) and shared by both results constructors, `ContFrag*Classifier.get_posterior`, and `get_HPD_spatial_coverage`.
- `analysis.distance2D.get_map_estimate_direction_from_track_graph` (and therefore `head_direction_simliarity` / `get_ahead_behind_distance2D`) with `precomputed_distance=True`: crashed with `AttributeError: 'generator' object has no attribute 'items'` under networkx ≥ 3, because the all-pairs form of `nx.shortest_path` returns a generator of `(source, {target: path})` pairs in networkx ≥ 3.5 rather than the dict it returns in 3.0–3.4. Both return types are now handled (the generator is iterated lazily; the older dict via `.items()`), so it works across the pinned `networkx >= 3.0` range. (#40)
- `visualization.movie.make_single_environment_movie`: the bottom multiunit firing-rate panel went blank after the first parallel chunk. `_render_single_env_frame` gated the bottom-axis limits on `frame_idx == 0`, but `create_parallel_video` renders contiguous frame chunks in separate worker processes, so only the worker owning frame 0 ever set them; every later chunk drew the rate line off-screen. The limits are now initialized on the first frame each worker renders, mirroring the existing posterior-mesh pattern. (#42)
- `analysis.distance2D.get_map_estimate_direction_from_track_graph` with `precomputed_distance=True`: on a disconnected track graph, an unreachable head-position/MAP pair silently indexed `node_positions[-1]` (the `-1` path sentinel) and produced a plausible but wrong heading. Unreachable pairs now emit a warning and return `NaN`, mirroring `get_2D_distance` (which warns and stores `inf`).
- `continuous_state_transitions.RandomWalk`: a `direction=` argument was silently ignored unless the environment was a fitted N-D grid with `use_manifold_distance=True` — under the default `use_manifold_distance=False`, or when a `track_graph` was present, the directional constraint was dropped and a plain random walk returned. `make_state_transition` now raises a `ConfigurationError` for these configurations instead of silently ignoring `direction`.

### Changed

- `analysis.distance2D.head_direction_simliarity` and `get_ahead_behind_distance2D`: docstrings described `head_direction` as shape `(n_time, 2)`, but the implementation requires a 1-D array of heading angles in radians `(n_time,)` (consistent with the 1-D sibling `get_ahead_behind_distance`). Passing the documented 2-D vector raised a broadcasting `ValueError`. Docstrings now document the angle contract; the implementation is unchanged. (#41)
- EM iterations where the marginal log-likelihood decreased (previously silent) now emit a `UserWarning` describing the iteration index, before/after log-likelihoods, and change magnitude — using the same `warnings.warn` channel as the other EM/GMM/GLM fit-quality diagnostics (the per-invocation decode-time degenerate/NaN-timestep diagnostics in `core` remain `logger.warning`). The iteration index is also appended to `em_monotonicity_violations_`.
- EM that exits via `max_iter` without converging (previously silent) now emits a `UserWarning` describing the final log-likelihood change, the tolerance, and that fitted parameters may be biased.
- The final E-step now checks that the post-M-step log-likelihood did not decrease by more than `tolerance`; a `UserWarning` flags inconsistencies between the E-step and the M-step output.
- **Note on previously-silent issues now surfaced:** the sorted-spikes GLM encoding path can still trip the new convergence warnings on genuinely non-converged fits (now gated on a large final gradient rather than the noisy `success` flag). The `test_sorted_spikes_glm_encoding_runs_end_to_end` integration test additionally trips the max-iter and final-E-step warnings under default parameters — root cause documented in issue #31 (GLM M-step uses the Local-only marginal as weights for an emission shared across all states, breaking the EM monotonicity guarantee). These are previously-silent issues now made visible, not regressions. A breadcrumb comment at the encoding-update site in `models.base` points to #31; the principled fix is tracked there.
- `core.filter` and `core.filter_covariate_dependent` are now plain Python wrappers (around the jitted `_filter_jit` / `_filter_covariate_dependent_jit`) that add the host-side degenerate/NaN diagnostics, rather than being `jax.jit` objects themselves. `jax.jit(filter)(...)` and composing them inside an outer transformation still work (the diagnostics are skipped under tracing), but code relying on the module-level objects being jitted callables (e.g. `filter.lower(...)` or jit-object identity) should jit `_filter_jit` directly.
- `core.check_converged`: the `is_increasing` monotonicity check is now **relative** — it flags a decrease only when `(curr - prev) / avg_magnitude < -tolerance`, matching the relative definition of `is_converged`, instead of the previous absolute `(curr - prev) >= -1e-3`. Because the marginal log-likelihood is a sum over timesteps, an absolute slack spuriously flagged negligible floating-point decreases on large datasets. The final-E-step consistency check in `models.base` now reuses `check_converged` so the in-loop and final checks share the identical relative slack.
- `model_checking.posterior_consistency.posterior_consistency_hpd_overlap`: docstring expanded with a Notes block explaining that the metric is the containment coefficient (`|A∩B| / min(|A|, |B|)`) — asymmetric — rather than Sørensen-Dice or Jaccard. The implementation is unchanged.
- `model_checking.posterior_consistency` (`posterior_consistency_kl_divergence` and `posterior_consistency_hpd_overlap`): corrected the input-shape docstrings — both require flattened `(n_time, n_position_bins)` input, not the previously-documented `(n_time, n_x_bins, n_y_bins)` (which raises), and the Sørensen-Dice formula in the Notes block now includes the factor of 2 (`2|A∩B| / (|A| + |B|)`). Docstrings only.
- `simulate.simulate_poisson_spikes` now consistently returns Poisson **counts** across the package. Previously two same-named functions in `simulate/simulate.py` and `simulate/sorted_spikes_simulation.py` had contradictory semantics (counts vs binary indicators). Callers needing a boolean indicator should apply `> 0`; all in-repo consumers already do this.
- `simulate.get_trajectory_direction` now consistently returns `(direction_label, is_inbound)`. The 1-value variant in `simulate/simulate.py` has been removed; all callers in this repo unpack both values.
- `simulate.simulate_position` retains the velocity-based semantics from `simulate/simulate.py` and is exported at the package level. The period-based sinusoid that previously shared the name in `simulate/sorted_spikes_simulation.py` has been renamed to a private `_simulate_sinusoidal_position_by_period` used only by the sorted-spikes-specific simulator flows. This preserves golden-regression trajectories.
- Shared simulator utilities (`simulate_time`, `simulate_place_field_firing_rate`, `simulate_neuron_with_place_field`, `simulate_poisson_spikes`, `get_trajectory_direction`) now live in `non_local_detector.simulate._common` and are re-exported from `non_local_detector.simulate`. Notebooks that imported them from `non_local_detector.simulate.sorted_spikes_simulation` should switch to `from non_local_detector.simulate import …`.
- `Environment` no longer overrides `__eq__` to compare against strings. Two `Environment` instances are now equal iff all their dataclass fields are equal. `Environment` instances are hashable again (identity-based hash; the post-fit numpy / networkx attributes have no meaningful value-hash). Code that relied on `env == "name"` returning `True` must switch to `env.environment_name == "name"` or the new `find_environment_by_name(environments, "name")` helper.
- `ObservationModel` no longer overrides `__eq__`. Equality now compares all four fields (`environment_name`, `encoding_group`, `is_local`, `is_no_spike`); previously `is_local` and `is_no_spike` were silently ignored. `ObservationModel` is hashable via `@dataclass(unsafe_hash=True)`. **User-visible side effect:** code that builds `np.unique(...)` over a list of observation models will now treat `is_local`/`is_no_spike`-distinct models as distinct (previously they collapsed). Default model configurations don't trigger this; a hand-built `observation_models` list whose entries share `(env_name, encoding_group)` but differ on `is_local`/`is_no_spike` will fit one encoding model per entry instead of collapsing.
- `clusterless_algorithm_params` and `sorted_spikes_algorithm_params` on every detector default to `None`. The constructor stores the user's argument as-is (sklearn convention; required for `clone()` round-trip). The dict copy and default resolution happen lazily at fit time via the new `_resolve_*_algorithm_params` helpers. The previous mutable-default-kwarg behavior (every detector aliasing the same module-level dict) is fixed because the resolver returns a fresh copy on each call. **User-visible side effect:** a user-supplied dict is no longer defensively copied at construction — `d.clusterless_algorithm_params is user_dict` after construction. Mutations the user makes to their own dict between construction and fit will be observed by the fit. To get isolated state, pass a fresh dict (`detector = ClusterlessDecoder(clusterless_algorithm_params=dict(my_params))`).

### Removed

- `environment.order_boundary` and `environment.get_track_boundary_points`: both called `nx.from_scipy_sparse_matrix`, which was removed in NetworkX 3.0. Neither was used anywhere outside their own module. The now-unused `from sklearn.neighbors import NearestNeighbors` import was removed alongside them.
- `discrete_state_transitions.estimate_joint_distribution`, `multinomial_neg_log_likelihood`, `multinomial_gradient`, `multinomial_hessian`, `set_initial_discrete_transition`: orphaned v1 M-step paths superseded by `_aggregate_xi_by_state_jax` / `_transition_pair_stats_jax` in c339fa9 (#24) and a19deb1. No remaining production callers.
- `likelihoods.clusterless_gmm.EncodingModel` dataclass: declared but never returned; comment marked it deprecated. The return-type annotation on `fit_clusterless_gmm_encoding_model` is updated to `dict` to match the actual return shape, and its Returns docstring is corrected to list the nine keys the function actually returns (the previous list named keys such as `occupancy_bins`, `log_occupancy_bins`, `position_time`, and the `gmm_*` config arguments that are never returned).
- Duplicate `simulate_time`, `simulate_place_field_firing_rate`, and `simulate_neuron_with_place_field` definitions in `simulate/sorted_spikes_simulation.py` (bit-identical to the versions in `simulate/simulate.py`). All hoisted into `simulate/_common.py` as the single source of truth.

### Deferred

- Canonical `clusterless_kde` consolidation (originally planned for this release): a benchmark uncovered an `is_local=True` NaN bug in `clusterless_kde_log` on the golden NonLocal fixture (issue #32). Switching the canonical path now would silently regress `test_nonlocal_detector_golden_regression` (max posterior diff 0.97 vs 1e-6 tolerance). Will ship as a follow-up release once #32 is fixed. Both `clusterless_kde` (probability-space) and `clusterless_kde_log` algorithm keys remain available; `clusterless_kde` continues to be the default.
